# Reward-credit audit before the factorial pilot

Inspected frozen revision4 `relative_bonus`/`rollout_cost`, revision5 `ExecutionEnv.step`/`Execution.step`, revision7 numerical worker/observer kernels, and revision9 PPO training. These observations motivate a new experiment; they do not establish that the old reward was the sole cause of regression.

| Finding | Evidence | Consequence | Pilot response |
|---|---|---|---|
| Reward can refer to an older packet | Execution returns `submitted=False` while pending; `packet_sequence` can differ from the latest sampled action. Old bonus uses applied `command`, not current proposal identity. | Same-tick bonus is not clean proposal-specific credit; delayed-return RL can in principle learn history, so this is an attribution limitation rather than proof of invalid PPO. | Predict the incremental effect of the one current request before executing it. In-flight ignored actions receive no credit or actor/entropy gradient. |
| Old continuation differs from deployment | `rollout_cost` uses `true_feedback` for steps1–9, bypassing observer/worker/gate on continuation. | Counterfactual optimism and mismatch are possible. | Both forecast branches retain current observer covariance/delayed raw measurement and actual worker/gate; only the current proposal differs. |
| Old baseline is full LQR | Old bonus compares current command against LQR from the current physical state. | It includes effects of held packets; it does not isolate a new request from existing execution history. | New baseline is the same execution history with a zero *new* request. Future requests are zero in both branches. |
| Dense reward mostly reflects baseline tracking | Positive tracking/survival reward accrues even when no correction is submitted or applied. | A large common component can dilute sparse incremental credit; this is a hypothesis about learning, not an actor-input leak. | Credit arms use bounded normalized200ms incremental lateral cost plus actual failure penalty, without old common positive components. |
| PPO KL is local, not a student anchor | SB3 target KL compares each minibatch with its rollout policy. Revision9 observed cumulative drift and higher teacher regret. | Small successive updates can forget supervised decisions. | Fixed coefficient1 KL(student||actor), half current and half existing TRAIN-observation replay; frozen student, no new labels. |

The new reward is a privileged **model-predicted** counterfactual, not an actual future observation. It uses a zero-innovation forecast, which can be biased. It does not receive actual future noise, fit on DEV/test data, or add hidden actor features. Original-object branch replay tests validate implementation consistency, not forecast validity. Only independently selected/fresh closed-loop comparisons can establish a tracking benefit.

Four arms isolate the anchor factor and the credit package (counterfactual reward plus ignored-action masking): plain, anchor-only, credit-only, combined. They share supervised initialization, fresh matched critic/optimizer, physical interface and RL-transition budget. Compute overhead differs and is reported. This factorial design cannot separate the reward formula from the masking subcomponent within the credit package; that would need another predeclared experiment.
