# 1. Aapke LANS framework ka overall concept

Aapka framework autonomous vehicle ki path tracking ke liye hai. Ismein do controllers hain:

- LQR: Mathematical model ke mutabiq steering command generate karta hai.
- PPO: Learning ke zariye LQR ki steering mein correction suggest karta hai.

Phir latency aur aapke newly added Symbolic Supervisor ki madad se PPO correction ko control kiya jata hai. Fusion Layer final steering command generate karti hai.

# 2. Har notation ka meaning

## A. Tracking-error inputs

Aapke diagram ke left side par yeh four signals hain:

\\[ e_y,\quad \dot e_y,\quad e\_\phi,\quad \dot e\_\phi \\]

| Symbol             | Meaning                | Simple explanation                                                            |
| ------------------ | ---------------------- | ----------------------------------------------------------------------------- |
| \\(e_y\\)          | Lateral tracking error | Gaari reference path se side mein kitni door hai.                             |
| \\(\dot e_y\\)     | Lateral-error rate     | Lateral error kitni tezi se change ho raha hai.                               |
| \\(e\_\phi\\)      | Heading/yaw error      | Gaari ki direction aur reference path ki direction mein kitna difference hai. |
| \\(\dot e\_\phi\\) | Heading-error rate     | Direction ka error kitni tezi se change ho raha hai.                          |

Dot \\((\dot{})\\) ka matlab time ke respect mein derivative hai, yani quantity ke change hone ki rate.

Example: Agar \\(e_y\\) positive hai, toh gaari reference path ke ek taraf hai; lekin left/right ka exact matlab aapki coordinate convention par depend karega.

Notation consistency ke liye poore paper mein \\(e\_\phi\\) use karein, agar aap diagram mein yehi symbol rakh rahe hain. Agar manuscript mein \\(e\_\psi\\) use hota hai, toh ek notation select karke har jagah consistent rakhein.

## B. LQR block

### LQR — Analytical Controller

Input: tracking-error states

Output:

\\[ \delta\_{LQR} \\]

\\(\delta\_{LQR}\\) ka matlab LQR ki calculated front-wheel steering command hai.

LQR vehicle ke mathematical model aur feedback gain ke mutabiq correction calculate karta hai. Yeh aapke system ka baseline controller hai. Iski stability guarantee specified model aur operating assumptions ke under hi apply hoti hai.

## C. Observation Builder aur PPO

Observation Builder tracking errors aur available features ko PPO ke liye suitable input representation mein convert karta hai.

| Symbol             | Meaning                                                                                      |
| ------------------ | -------------------------------------------------------------------------------------------- |
| \\(o_t\\)          | Time step \\(t\\) par PPO ka observation vector.                                             |
| \\(c_t\\)          | Cost-related features, agar aapke manuscript mein isi meaning ke saath define kiya gaya hai. |
| \\(t\\)            | Discrete time step.                                                                          |
| \\(\delta\_{Rt}\\) | PPO ka proposed residual steering correction.                                                |

PPO poori steering command generate karne ke bajaye LQR ki command mein correction suggest karta hai.

\\[ \delta\_{\text{candidate}} = \delta\_{LQR}+\delta\_{Rt} \\]

Yeh sirf preliminary combination hai; aapke updated framework mein Supervisor aur latency weighting bhi apply honge.

## D. \\(z_t\\) — Symbolic Supervisor ka input

Aapne Observation Builder se Symbolic Supervisor tak dashed arrow add kiya hai, jis par \\(z_t\\) likha hai.

\\[ z_t=\text{selected state/features} \\]

Ismein woh relevant, interpretable information hogi jo symbolic rules ko decision lene ke liye chahiye. Misal ke taur par:

\\[ z_t=[e_y,\dot e_y,e\_\phi,\dot e\_\phi] \\]

Agar aap speed ya preview errors bhi use karna chahte hain, toh unhein \\(z_t\\) mein include kar sakte hain. Lekin exact vector ko methodology mein define karna zaroori hai.

Important: \\(z_t\\) aur \\(o_t\\) ko automatically identical na samjhein. \\(o_t\\) PPO ka input hai, jabke \\(z_t\\) Supervisor ke liye selected features hain. Dono mein kuch features same ho sakte hain.

## E. Symbolic Supervisor

Supervisor ko teen inputs milte hain:

- \\(z_t\\): vehicle ki selected state/features.
- \\(\tau\\): measured latency.
- \\(\delta\_{Rt}\\): PPO ki proposed correction.

Supervisor explicit rules ke mutabiq decide karta hai ke residual accept, reduce ya reject karna hai.

Aapke diagram mein Supervisor ka output hai:

\\[ r_s \\]

Isko aap supervisor-approved PPO residual define kar sakte hain:

\\[ r_s=g_s(z_t,\tau,\delta\_{Rt})\\,\delta\_{Rt} \\]

Yahan \\(g_s\\) gating factor hai:

- \\(g_s=1\\): residual accept.
- \\(g_s=0\\): residual reject.
- \\(0\<g_s<1\\): residual reduce.

Yeh proposed mathematical definition hai. Actual \\(g_s\\) rules aur thresholds aapko methodology mein specify karne honge. \\(r_s\\) ko reward ke saath confuse hone se bachane ke liye notation table mein iska meaning clearly likhein.

## F. System Clock, Latency Monitor aur Adaptive Gain

System Clock

Control computation ka start aur end time record karta hai.

Latency Monitor

Measured computation latency calculate karta hai.

Adaptive Gain

Latency ke mutabiq PPO residual ka weight adjust karta hai.

### Latency notation

\\[ \tau=t\_{\text{end}}-t\_{\text{start}} \\]

Yahan \\(\tau\\) measured controller-computation latency hai. Aapke original manuscript mein measurement scope ko controller computation ke relevant operations ke mutabiq define kiya gaya hai. Isko sensor delay ya actuator delay ke saath mix nahi karna chahiye.

Adaptive Gain ka output:

\\[ \beta(\tau) \\]

- Low latency par \\(\beta(\tau)\\) high hota hai.
- Latency barhne par \\(\beta(\tau)\\) decrease hota hai.
- High latency par PPO correction ka influence kam ho jata hai.

Isliye \\(\beta(\tau)\\) aur \\(g_s\\) ka role alag hai: \\(\beta(\tau)\\) latency-based continuous weighting hai, jabke \\(g_s\\) symbolic-rule-based residual gating hai.

## G. Fusion Layer

Aapke updated framework ka final control equation yeh ho sakta hai:

\\[ \boxed{ \delta\_{\text{total}} = \operatorname{sat} \left[ \delta\_{LQR}+\beta(\tau)r_s \right] } \\]

| Symbol                          | Meaning                                                             |
| ------------------------------- | ------------------------------------------------------------------- |
| \\(\delta\_{LQR}\\)             | LQR ki baseline steering command.                                   |
| \\(r_s\\)                       | Symbolic Supervisor se approved PPO residual.                       |
| \\(\beta(\tau)\\)               | Latency-dependent weight.                                           |
| \\(\operatorname{sat}(\cdot)\\) | Steering command ko actuator ki allowed limits ke andar rakhta hai. |
| \\(\delta\_{\text{total}}\\)    | Final fused steering command.                                       |

Fusion Layer mein PPO residual do checks se influence hota hai: pehle Supervisor usay rule-based gate karta hai, phir Adaptive Gain uska latency-based weight adjust karta hai.

## H. Path Tracking Error Model

Yeh block controlled vehicle/path-tracking dynamics ko represent karta hai.

1. Fusion Layer se \\(\delta\_{\text{total}}\\) receive karta hai.
2. Vehicle model ke mutabiq response calculate hota hai.
3. Updated tracking errors generate hote hain.
4. Errors feedback ke zariye LQR aur Observation Builder tak wapas jaate hain.

Is tarah closed-loop control repeat hota rehta hai.

# 3. Aapke updated framework ka complete signal flow

\\[ \begin{aligned} \text{Tracking errors} &\rightarrow \text{LQR} \rightarrow \delta\_{LQR}\\\ \text{Tracking errors} &\rightarrow \text{Observation Builder} \rightarrow \text{PPO} \rightarrow \delta\_{Rt}\\\ \text{Observation Builder} &\rightarrow z_t \rightarrow \text{Symbolic Supervisor}\\\ \tau&\rightarrow \text{Symbolic Supervisor}\\\ (\delta\_{Rt},z_t,\tau) &\rightarrow \text{Symbolic Supervisor} \rightarrow r_s\\\ (\delta\_{LQR},r_s,\beta(\tau)) &\rightarrow \text{Fusion Layer} \rightarrow \delta\_{\text{total}} \end{aligned} \\]

Bhai, sabse important baat: Original LANS ki main contribution latency-aware LQR–PPO residual fusion hai. Aapka added Symbolic Supervisor ek proposed extension hai. Isko genuine Neuro-Symbolic contribution kehne ke liye explicit symbolic rules, mathematical definitions aur experiments se uska independent benefit demonstrate karna hoga.
